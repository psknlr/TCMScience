\caption{The TCMScience agent architecture, with each component named as in the code. (1) A request enters through the command line, the Python services or Studio and is labelled at ingress. (2) It passes to the planner, which (3) obtains a proposal from the language model only through call\_model and the ModelGateway. (10) Validated state is committed through the PersistenceGateway to four stores, and every gate's decision is appended to the hash-chained event store. Governance constrains the kernel and never executes. Colour has one meaning throughout: blue, the trusted kernel and what it releases; green, the capability plane; orange, governance; reddish purple, the scientist plane; vermillion, refusals; grey and dashed, the untrusted model.}

\begin{figure*}[!t]

\includegraphics[width=\textwidth]{IEEE_Fig_Compiler.pdf}
\caption{The scientific compiler. A program in the scientific intermediate representation (SIR), written by the model as JSON, by a builder or compiled from a skill contract, passes eight passes in order, each emitting one family of diagnostics (bars: the 71 codes by family and severity; an error refuses the program, a warning is reported). The structure pass stops the pipeline on error, because the later passes assume an acyclic graph. A program that compiles is lowered to the typed Plan that the PlanValidator checks as a whole (graph, authority, dataflow, budget, scientific) before the AgentLoopController runs any step. Every refusal returns to the ModelPlanner with its code, remedy and location, for a bounded number of repairs. The compiler can only refuse: it grants nothing the runtime would not.}

\end{figure*}

\begin{figure*}[!t]

\includegraphics[width=\textwidth]{IEEE_Fig_Snapshots.pdf}
\caption{How third-party data enter, as audited snapshots. A source card states the licence and the access paths in order of preference (bulk, API, manual import, web; web only after a person has approved it). A release is fetched, each raw file hashed; parsed into node and edge tables, dropped rows counted; normalized to InChIKey, Swiss-Prot and MONDO identifiers; and passed through a quality gate: a structural or licence problem fails the snapshot, and coverage below the card's minimum or drift above 20\% (the default) sends it to a person for review. The snapshot id is the key, the version and the first 12 hexadecimal digits of the SHA-256 of the manifest's content (raw files, parser code, tables, quality result, licence; nothing time-dependent); it is recorded on an append-only, hash-chained ledger, and every load re-hashes the tables and checks the id and the ledger head. Below, the 8 source cards, their access paths, the licence each card states and their role in the Gegen Qinlian decoction study. A run may use only the sources its skill declares, the cards enable and its policy allows, and its lock names every snapshot and the ledger head it read.}
\label{fig:snapshots}
\end{figure*}

\begin{figure}[!t]
\centering
\includegraphics[width=\columnwidth]{IEEE_Fig_InquiryLoop.pdf}
\caption{How the inquiry engine decides its next step (Inquiry.next\_step), with the default stopping rule. The model proposes rival explanations with a catch-all whose prior is at least 0.05, analyses with their costs, and what each explanation predicts each analysis will show, sealed before it runs. The engine stops at 64 steps; asks for new explanations, carved from the catch-all, once the catch-all holds 0.50 or more; when a leader reaches 0.95, runs the severe test (severity at least 0.8) or the replication it still owes against a live rival, and accepts the leader when none is owed; and otherwise runs the analysis with the most expected information per unit cost, if one offers at least 0.01 bits (analyses without sealed predictions must have them declared first). Belief moves only by the sealed predictions, and a design that cannot license an explanation's claim kind leaves that explanation fixed (INQ113). A stopped inquiry is provisional or undetermined; an accepted one is stated no more strongly than the licensing table allows.}
\label{fig:inquiry-loop}
\end{figure}
