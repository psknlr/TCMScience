# Studio v2 — full corpus, browser compute, one-line runner, phones

Binding design for the v2 work. It extends `CONTRACTS.md` (§1–§10); where the two disagree, this file wins until
its sections are folded into `CONTRACTS.md` (§11–§16 there). Measurements quoted here come from the v2
investigation (headless Chromium 141, Pyodide 314.0.7, a 4-vCPU Linux box, Cloudflare Workers Static Assets).

Principles that do not change: a call never raises (failures are data); evidence kinds are types; prediction ≠
fact; "no record" ≠ "safe"; refusals are results; a clinic output is a draft and signing is a person's act; the page
never names the upstream model vendor; nothing is published that its licence does not allow; every number the
browser computes either equals the native number bit for bit or is labelled as a different, declared method.

## §11 The full corpus (`/corpus/`, `tcmstudio.corpus`)

### 11.1 Packs and the publication gate

`tcmstudio/corpus/packs.py` holds the allowlist (`PACKS`) and the denylist (`NEVER_PUBLISHED`). The build refuses
a pack whose sources are not all allowlisted, and a test asserts the two lists never overlap.

| pack | content | sources (licence) | publication basis |
|---|---|---|---|
| `core` | curated TCM knowledge: herbs (seed 23 merged into materia 401), syndromes (seed 8 + clinic 19 = 27), curated formulas (seed 6 with 君臣佐使 + clinic 13 with roles unstated), safety records (seed 14 + clinic-derived 十八反/十九畏, pregnancy, toxicity), classical passages (seed 9), the name index | repo, MIT: `bioagent.tcm.knowledge.seed()`, `bioagent.sources.materia` + `registry/materia_taxa.json` (NCBI taxonomy, public domain), `bioagent/data/clinic_pack.json` | open licence |
| `formulas` | 中医方剂数据表: 84,294 rows (name, composition as written, parsed components, 出处, 炮制, 功效/主治 text, 使用方法, 注意) | `中医方剂数据表.xlsx` (sha256 `0ddb7ad8a00c077ce8f4ec0dca5f5756689821e646d39f8e3105a15c57d3ffe4`), licence **not stated** | **owner decision**: `{"decided_by": "IMPF-AI（science.impf.ai 站点所有者）", "date": "2026-10-08", "basis": "所有者决定在 science.impf.ai 公开发布；原表未声明来源与许可", "licence": "LicenseRef-owner-published-unstated", "commercial": "unknown"}` |
| `lotus` | for each materia herb: the source organisms matched (NCBI taxid first, then exact species name) and the natural products LOTUS records in them (InChIKey, name, formula, 2-D SMILES, reference count) | LOTUS frozen export 2026-04-13, Zenodo record 19360665 (CC-BY-4.0; cite doi:10.7554/eLife.70780) | open licence, attribution |
| `pathways` | Reactome lowest-level human pathways (UniProt members, names) + HGNC approved symbol ↔ UniProt | Reactome `UniProt2Reactome.txt` + `ReactomePathways.txt` (CC0-1.0), HGNC complete set (CC0-1.0) | open licence |

`NEVER_PUBLISHED` (with the reason each card records): NPASS, CMAUP (no licence stated), KEGG (academic only),
HERB, SymMap, ITCM, BATMAN-TCM, TCMBank, TCMIO, DCABM, dbPTH, DDID, TTD, TCMToxDB, IMPPAT, gutMGene, HKBU exports,
HKCMMS, NP-MRD, and any dataset whose `tcmdb` licence class is `non-commercial`, `no-derivatives` or `unknown`.
Users reach those through the runner (`tcmdb fetch`) or their own browser, from the original site.

Each pack in the manifest carries `title {zh,en}`, `licence` (SPDX or LicenseRef), `attribution` (text shown on the
attribution page), `sources[]` (`{name, version, url, sha256?, retrieved, licence, citation}`), `publication`
(`{basis:"open-licence"}` or the owner decision above), `evidence_ceiling` and `limitations[]` (zh and en).

Evidence and limits per pack (they travel into every envelope that reads the pack):
- `core`: seed records keep their tiers. Materia layer = identity only (names, species, part); no 性味/归经/功效 for
  the 378 non-seed herbs (empty, never defaulted). Clinic layer = **draft, not reviewed by a licensed TCM
  practitioner** (`clinic_pack.json` review_status). A value the source does not state is `""` / `null` / `"unstated"`,
  never a default: no `toxicity:"无毒"`, no `dosage_form:"汤"`, no invented severity (clinic-derived 十八反/十九畏 records
  carry `severity:"unstated"`).
- `formulas`: a compiled reference record; `evidence_ceiling: "EXPERT_EXPERIENCE"`; 出处 is a pointer, not a quoted
  passage (never CLASSICAL_TEXT); roles are not recorded; the 功效 column holds 主治 text and partly modern editorial
  notes ("现用于…"); licence unstated, published by owner decision, commercial use unknown (a commercial run refuses it).
- `lotus`: "LOTUS records that the compound was reported in the organism"; presence ≠ active constituent, ≠ content,
  ≠ efficacy; organism ↔ herb match is by taxon, not by the processed drug.
- `pathways`: annotation (what a protein takes part in), not what any compound does.

### 11.2 Published layout

```
/corpus/latest.json                       no-cache: {schema, snapshot_id, manifest, sha256}  (pointer for runners)
/corpus/manifest.<sha12>.json             immutable; pinned by runtime/boot.json
/corpus/o/<sha256 first 32 hex>.gz        immutable objects: gzip (mtime 0, level 9) of UTF-8 compact JSON
/corpus/ATTRIBUTION.md                    generated
/attribution.html                         generated page (linked from About and from every corpus envelope)
```

`.gz` files are served by Workers Static Assets as `application/gzip` **without** `Content-Encoding` (verified), so
the SHA-256 in the manifest is over exactly the bytes the client receives; clients gunzip themselves (Python `gzip`,
JS `DecompressionStream("gzip")`). `_headers`: `/corpus/o/*` and `/corpus/manifest.*` → `Cache-Control: public,
max-age=31536000, immutable`; `/corpus/*` also `Access-Control-Allow-Origin: *` and `Cross-Origin-Resource-Policy:
cross-origin` (a runner-served page on 127.0.0.1 reads the public corpus).

Manifest:
```jsonc
{
  "schema": "tcmstudio.corpus/1",
  "snapshot_id": "tcmcorpus-<YYYY.MM.DD>-<sha12>",   // date = the data date set in packs.py (not the build clock);
                                                      // sha12 over the sorted "path sha256" lines of objects
  "data_date": "2026-10-09",
  "packs": { "core": {…}, "formulas": {…}, "lotus": {…}, "pathways": {…} },   // §11.1 fields + counts
  "objects": { "<logical path>": {"url": "o/<hash32>.gz", "sha256": "<64 hex>", "bytes": n, "raw_bytes": n, "pack": "core"} }
}
```
The build is deterministic: the same sources give the same objects, the same manifest bytes and the same name.

### 11.3 Objects (logical paths)

- `core/core.json` — `{herbs:[Herb], syndromes:[Syndrome], formulas:[CuratedFormula], safety:[SafetyRecord],
  passages:[Passage], names:{<name>: [[kind, id], …]}}`. `names` covers herb names + typed aliases (synonyms only;
  processed forms such as 炙甘草/法半夏 are kept on the herb as `aliases[].kind:"processed"` and are **not** resolved
  to the crude drug), syndrome names, curated formula names. Formula-table names are **not** in it (separate universe:
  adding them makes `桂枝汤` resolve to 23 candidates).
  - `Herb = {id:"herb.<materia id>", materia_id, chinese, pinyin, latin, category, part, species:[{name, taxid}],
    aliases:[{name, kind:"synonym"|"processed"|"product"|"part"}], nature, flavours[], meridians[], actions[],
    toxicity, dose:{min_g, max_g, note}|null, pregnancy, cautions[], layers:{<field>: "seed"|"materia"|"clinic"},
    formula_count, compound_count}` (id stays `herb.shudihuang` for materia `shudi`, the seed's id).
  - `Syndrome = {id, chinese, category, main[], secondary[], tongue[], pulse[], principle, formulas:[{id|null, name}],
    parent, layer:"seed"|"clinic"}`.
  - `CuratedFormula = {id, chinese, source, ingredients:[{herb_id|null, name, dose, role:"君"|"臣"|"佐"|"使"|"",
    processing}], roles_recorded:bool, indications:[syndrome ids], dosage_form, modifications[], layer}`.
  - `SafetyRecord = {id, kind:"incompatibility"|"contraindication"|"caution"|"toxicity"|"interaction",
    subject:{id, name}, counterpart:{id|null, name}|null, rule, severity:"low"|"moderate"|"high"|"critical"|"unstated",
    population, note, evidence_tier, citation, layer}`.
- `formulas/index.json` — `{names:[…], source_ids:[…], sources:[…]}`; row `r` is `names[r]`, `sources[source_ids[r]]`.
- `formulas/rows/<NNNN>.json` — chunk `NNNN = rowno // 500`: `{start, rows:[{rowno, id, name, source, composition,
  components:[[name, dose, processing, materia_id|null]], preparation, indications, usage, cautions}]}`. `rowno` is the
  0-based data-row order of the xlsx and the unique key (`id` from `bioagent.sources.formulas` has 28 collisions).
- `formulas/by-herb/<materia id>.json` — `{herb, count, rows_delta:[…]}` ascending row numbers, delta-encoded.
- `formulas/stats.json` — totals precomputed at build time (rows, resolved rows, components, per-herb counts, top
  出处 books). Never computed in a phone's browser (parsing all rows there costs 19 s and 349 MB).
- `lotus/<materia id>.json` — `{herb, organisms:[{name, taxid, matched_by}], compounds:[{ik, name, formula, smiles,
  refs}]}` (sorted by refs desc, then ik).
- `pathways/reactome.json` — `{version, pathways:{"R-HSA-…": {name, members:[UniProt…]}}}` (lowest level,
  *Homo sapiens*); `pathways/hgnc.json` — `{version, symbol_to_uniprot:{…}, uniprot_to_symbol:{…}}`.

Committed open-data extracts (inputs of the `lotus` and `pathways` packs) live in `studio/corpus/data/` with
`SOURCES.json` (upstream URL, version, sha256 of the upstream file, retrieval date, licence, the command that
rebuilds them: `python3 studio/corpus/extract_open.py`). CI never downloads them; the corpus build reads the
committed files. Schemas: `lotus-herbs.json.gz = {schema:"tcmstudio.corpus.lotus/1", source:{…}, herbs:{<materia
id>: {organisms:[…], occurrences:[[ik, refs], …]}}, compounds:{<ik>: {name, formula, smiles}}}`;
`pathways.json.gz = {schema:"tcmstudio.corpus.pathways/1", sources:[…], pathways:{…}, symbol_to_uniprot:{…}}`.

### 11.4 Readers and receipts

Python: `tcmstudio.corpus.Corpus(fetcher)` with `manifest`, `snapshot_id`, `manifest_sha256`, `get(path)` (verifies
SHA-256, gunzips, parses, keeps an LRU of parsed objects), `reads()` (ordered, de-duplicated `{path, sha256}`).
Fetchers: `DirFetcher(site_dir)` (a built `_site`), `HttpFetcher(base_url, cache_dir)` (runner; disk cache first,
verified on read; downloads honour the runner's network setting), `XHRFetcher(base_url)` (Pyodide only: synchronous
XHR from the worker, `responseType="arraybuffer"`; the HTTP cache serves repeats). `default_corpus(ctx)`:
`ctx["corpus"]` (`{base_url, manifest, sha256}`, passed by the worker) → `$TCMSTUDIO_CORPUS` (dir or URL) → a built
site next to the runner (`--web`) → `<home>/corpus/` cache + `https://science.impf.ai/corpus/latest.json`.
A missing corpus is `status:"failed"`, `error.type:"unavailable"` with the remedy (`tcmstudio corpus fetch`).

JS (page): `web/js/corpus/reader.js` reads the same manifest (from `runtime/boot.json` → `corpus`), fetches objects
with Cache Storage (`tcmstudio-corpus-v1`, budget per device class §15), verifies SHA-256 and gunzips.

Every envelope that read the corpus carries `receipt.corpus = {snapshot_id, manifest_sha256, reads:[{path, sha256}]
(≤ 50), reads_total}` and `governance.licences` for each pack read; the formula pack adds its owner-decision note.

| tool | arguments | returns |

## §12 Live connectors in the browser

- `tcmstudio/browserhttp.py` — on `sys.platform == "emscripten"`, `install()` makes `urllib.request` work through
  synchronous XHR in the worker: it wraps `urllib.request.build_opener` so every opener gets an `XHRHandler`
  (`http_open`/`https_open`; Pyodide has no `ssl`, so stock urllib has no HTTPS handler). Requests drop the headers a
  browser forbids (User-Agent, Host, Connection, Content-Length, Accept-Encoding, Cookie, Origin, Referer); a
  cross-host redirect (`responseURL` host ≠ request host) is refused, as the backend would refuse it; HTTP errors
  become `HTTPError`; a CORS or network failure (XHR status 0) becomes `URLError("browser_cors: <host> does not allow
  requests from web pages (no CORS); use the local runner")`. Installed by the worker's boot code.
- `tcmstudio/data/browser_hosts.json` — `{schema:"tcmstudio.browser-hosts/1", checked:"<date>", method, hosts:{<host>:
  {cors:true|false|null, preflight:true|false|null, evidence}}}`, produced by `studio/scripts/probe_cors.py`
  (each connector's example request with `Origin: https://science.impf.ai`, plus an OPTIONS preflight for non-simple
  requests). `null` = not reachable from where the probe ran (unknown, stays runner-only).
- Catalog: a connector entry is `exec: ["browser","runner"]` when its host has `cors:true` (and `preflight:true` when
  its request is not CORS-simple); otherwise `["runner"]` with `needs: ["the local runner (this source does not allow
  requests from web pages)"]`. `literature_search` and `connector_call` follow their connectors. Network approval
  in the page is unchanged (a network tool needs the user's approval in either runtime).

## §13 Browser compute: device classes, the Python pool, accelerators

### 13.1 Device classes (`web/js/runtime/device.js`)

`classify({cores, memory_gb, mobile, ios, webgpu}) → {cls, python_workers, js_workers, sci_auto, corpus_cache_mb,
gpu:"hardware"|"software"|"none"}`. Mobile = `navigator.userAgentData?.mobile` or UA `Android|iPhone|iPad|Mobile`, or
a Mac with `maxTouchPoints > 1` (iPad). iOS reports 4 cores for every iPhone and has no `deviceMemory`.

| class | when | python_workers | js_workers | sci_auto | corpus cache |
|---|---|---|---|---|---|
| `phone-low` | mobile and `memory_gb ≤ 2` | 1 | min(2, cores−1) | false | 64 MB |
| `phone` | mobile otherwise (every iPhone; Android with memory 3–4 or unknown) | 1 | min(2, cores−1) | false (numpy only) | 64 MB (256 if `persist()` granted) |
| `tablet` | iPad, or mobile with `memory_gb ≥ 6` | 2 | min(4, cores−1) | false | 256 MB |
| `desktop` | not mobile | clamp(min(cores−1, ⌊memory_gb·1024/4/300⌋), 1, 4) (memory unknown → 2) | min(cores−1, 8) | true | 512 MB |

Settings (`settings.compute.browser = {workers:"auto"|1..8, gpu:"auto"|"off"}`) may lower the numbers, never
raise them above `cores−1`. `gpu:"hardware"` only when an adapter exists and is neither `isFallbackAdapter` nor a
software renderer (SwiftShader, llvmpipe, lavapipe, Microsoft Basic Render).

### 13.2 Python worker pool (`web/js/runtime/pool.js`, used by `browser.js`)

- Worker 0 is the primary: it runs stateful calls (kinds `skill`, `clinic`, `system.audit_verify`; IDBFS-persisted)
  and everything while the pool has one worker. Secondaries run stateless calls only, with `persist:false`.
- A secondary is spawned only when a call waits while every live worker is busy and the pool is below its size;
  boots are staggered (one at a time); idle secondaries are terminated after 60 s on phones/tablets and 10 min on
  desktops. The agent already runs one step's tool calls with `Promise.all`, so a pool makes them parallel.
- Shared compiled module: the page compiles `pyodide.asm.wasm` once (`WebAssembly.compileStreaming`) and sends the
  `WebAssembly.Module` to each worker in a structured message `{type:"wasm-module", module}` before `init`; the worker
  serves it to Pyodide by overriding `WebAssembly.instantiateStreaming`/`instantiate` for that URL. (Several workers
  compiling at once made 2–3 of them hang forever with a swallowed "compilation aborted".) Boot timeout 90 s → one
  respawn, then the pool shrinks.
- Each worker has its own interrupt buffer; Stop interrupts the worker running that call.
- `BrowserRuntime.info()` and status events add `pool: {size, live, busy, cls}`.

### 13.3 Compiled-module cache fix

The pycache tar is saved per bundle hash and Pyodide version **for the bundle tree only** (`/pycache/opt/tcms/site`):
site-packages modules (numpy/scipy/pandas ship sources) are never captured (they grew the tar from 6 MB to 31 MB and
every later boot by 0.75–3.8 s). Secondaries restore it, never write it.

### 13.4 Accelerators

Protocol (browser only; the runner always computes in Python):
1. The worker passes `context.accel = {kernels:["np-null-mt/1"], prefer:"auto"|"gpu"|"cpu"}` when the page has an
   accelerator host.
2. A tool that can use a kernel returns, instead of an envelope, `{"__accelerate__": {"token", "kernel", "input"}}`
   from `tcmstudio.dispatch.call_json` (the resume state stays in Python under `token`, bounded, 10-minute expiry).
3. The worker posts `{type:"accelerate", id, token, kernel, input}` to the page; the page's `AccelHost`
   (`web/js/accel/host.js`) runs it and answers `{type:"accelerated", id, token, ok, result|error}`; the worker calls
   `tcms_resume(token, result_json)` and returns that envelope as the call's reply. An error resumes with
   `{"error": …}` and Python computes natively.
4. Python verifies before it trusts: it recomputes a deterministic sample (the first and the last pathway, and one
   chosen by `seed`) natively and compares the integers; any mismatch discards the accelerated result, recomputes
   everything natively and records it. `receipt.accel = {engine:"webgpu"|"js-workers"|"python", device, kernel,
   kernel_digest, verified:[ids], mismatch:false, ms}`; `receipt.device` is `"webgpu"` when the GPU did the work.

Kernel `np-null-mt/1` — the degree-matched permutation null of `bioagent.analysis.network_pharmacology` step 4,
**the same method, bit for bit**:
```jsonc
// input
{"seed": "20260923", "permutations": 1000,
 "pools": [[<protein index>, …], …],          // pools[b] in Python list order (ordered by (degree, id))
 "wanted": [[b, k], …],                        // sorted(wanted.items())
 "pathways": [{"id": "reactome:R-HSA-…", "members": [<protein index>, …], "observed": <int>}]}
// output
{"at_least": [<int per pathway>], "engine": "…", "device": "…", "kernel_digest": "sha256:…", "ms": <int>}
```
For each pathway, independently: `rng = random.Random(f"{seed}:{id}")` (CPython seeding of a str: `int.from_bytes(s +
sha512(s), "big")` → `init_by_array` over its little-endian 32-bit words), then `permutations` times: draw =
concatenation over `wanted` of `rng.sample(pools[b], k)` (CPython ≥ 3.11 `sample`: `_randbelow` by
`getrandbits(bit_length)` rejection; pool branch when `n ≤ 21 + 4**ceil(log(3k, 4))` for `k > 5` (21 otherwise),
set branch otherwise); `at_least += |members ∩ draw| ≥ observed`.
Engines: `js-workers` (exact port, a pool of plain JS workers sized by §13.1; 17.7× native on 4 cores); `webgpu`
(one invocation per pathway, MT19937 state, pool scratch and a selection bitset in storage buffers, permutations
advanced in passes of ≤ 100 per dispatch so no submit runs long enough to trip a GPU watchdog; u32 only). `auto` picks
`webgpu` on a hardware adapter when there are ≥ 64 pathways, else `js-workers`. The host cross-checks a GPU result on
two pathways with the JS engine before returning it. Never: p-values, BH or any float on the GPU (WGSL has no f64).

The `pathway_enrichment` tool (§14) is the first user. `web/js/accel/bench.js` runs a synthetic world (the
investigation's 1,399-pathway world, seeded) on each available engine and reports times and equality (Settings →
Compute → "浏览器算力测试").

## §14 `pathway_enrichment` (core tool, browser + runner)

`pathway_enrichment {targets:[UniProt accession | HGNC symbol | "uniprot:…"], background:"reactome" | [ids],
pathway_min_size=5, pathway_max_size=500, fdr=0.05, permutations=1000, permutation_alpha=0.05, degree_bins=10,
seed=20260923, limit=25}` over the `pathways` pack: steps 3 and 4 of `network_pharmacology.py` with the same
`Parameters` defaults and the same ids (`uniprot:<acc>`, `reactome:<stable id>`), so its rows equal the pipeline's
rows on the same inputs (a test proves it on the pipeline's own test world). Hypergeometric + BH on the CPU (f64);
the null through the accelerator in the browser. Symbols map through HGNC; unmapped inputs are listed, never guessed.
Limitations: annotation over-representation only; the whole-annotation background favours well-studied proteins (the
degree-matched null controls degree only); a target list from predictions inherits their uncertainty.

## §15 Phones

- Device classes (§13.1) decide workers, the scientific tier (scipy/pandas load on phones only after the user agrees
  to a call that needs them) and the corpus cache budget.
- Pyodide is **self-hosted** on science.impf.ai (`/pyodide/314.0.7/`: the core files and the lockfile closure of every
  package a browser entry may load; each file's SHA-256 pinned in `tcmstudio/pyodide_host.py`, checked when CI
  downloads it). jsDelivr lost its China ICP licence in 2021; same-origin files also satisfy COEP without CORP.
  `boot.json → pyodide.index_url` is `pyodide/314.0.7/` (relative to the site) when self-hosted.
- Corpus objects are fetched lazily (one formula: 1 request, ~35 KB; one herb's formula list: ~136 KB).
- Long computations take a screen wake lock from the user's tap and report progress; work is chunked (≤ 2 s per
  GPU submit, per JS chunk).
- `navigator.storage.persist()` is requested after the first project is created; iOS shows an "Add to Home Screen"
  hint (Safari evicts storage after 7 days without a visit; Home Screen apps keep their own).
- Tests: `e2e/lib/throttle.mjs` slows the whole renderer process (SIGSTOP/SIGCONT cycles; DevTools CPU throttling does
  not slow workers, so the old "4× phone" figure measured an unthrottled worker). Timings are annotations.

## §16 One-line runner install and pairing

- `https://science.impf.ai/install.sh` (macOS/Linux: `curl -LsSf https://science.impf.ai/install.sh | sh`) and
  `install.ps1` (Windows: `powershell -ExecutionPolicy ByPass -c "irm https://science.impf.ai/install.ps1 | iex"`).
  Options: `--cn` (PyPI and Python mirrors for mainland China), `--autostart`, `--gpu`, `--extras <names>`,
  `--uninstall [--purge]`, `--no-start`. They use `uv` (installed into `~/.tcmscience/bin` if missing, from the copy
  science.impf.ai hosts), download the three wheels (`psh`, `bioagent`, `tcmstudio`) by URL, **check each SHA-256
  themselves** (`uv tool install` ignores `#sha256=`), install with Python 3.12 (`uv tool install`, never by package
  name: PyPI has unrelated `bioagent` and `psh` packages), record `<home>/install.json` (`{method:"uv-tool", version,
  options}`), start `tcmstudio serve` and open the pairing link.
- `tcmstudio/release.py` (build): wheels into `_site/runner/<sha12>/<wheel filename>`, `_site/runner/manifest.json`,
  the hosted uv archives with pinned hashes, and the two scripts rendered from `studio/install/install.{sh,ps1}.in` with
  the URLs and hashes. The tcmstudio wheel contains the web app, so an installed runner serves `/` itself.
- Pairing without a long-lived token in the URL: the runner prints/opens `https://science.impf.ai/#pair=<base64url(JSON
  {url, code})>` where `code` is single-use, 128-bit, valid 10 minutes; the page trades it at `POST /api/pair/claim
  {code}` (Origin-checked, no token) for the token. Old `{url, token}` links still work.
- Runner already running (autostart): the page's "连接本机 Runner" calls `POST /api/pair/request` → `{request_id,
  secret, code6, approve_url}`; the user opens `approve_url` (`http://127.0.0.1:8765/pair?r=…`, a runner page with
  `frame-ancestors 'none'`, a form nonce, and the requesting origin shown) and confirms the 6-digit code; the page polls
