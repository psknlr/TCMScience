# Connector coverage by verification level

Generated by `studio/scripts/connector_coverage.py` from the tool catalog and the committed records; one row per operation in [`connectors.csv`](connectors.csv). `--check` keeps it current (`studio/runner/tests/test_connector_coverage.py`).

Operations: 444, from 117 sources. Each level is reported on its own. A mock result is never counted as a live one, and a live call made from a maintainer's machine is not a call through the deployed site.

| Level | What it shows | Where it comes from | Operations |
|---|---|---|---|
| `mock_transport` | the operation, called through Studio's dispatcher as the browser calls it, sends exactly one request to its declared host, the same method, URL and body as `verify_connectors.py`, and a stand-in transport's HTTP 200 comes back as a succeeded envelope. Nothing about the upstream service | this script, offline, on every `--check` | PASS 444 |
| `offline_refusal` | with web access off, the call is refused (`network_off`) before any request | this script, offline | PASS 444 |
| `live_upstream` | the real upstream answered the operation's example through `HTTPBackend`, on the date recorded | [`BioScience-Harness/data/connector_live_verification.csv`](../../../BioScience-Harness/data/connector_live_verification.csv), written by `scripts/verify_connectors.py` and changed only by a reviewed commit | PASS 444; dated 2026-09-17 to 2026-10-07 |
| `live_gateway` | the operation called from a browser through the deployed gateway to the real upstream | no committed record exists | not verified 444 |
| `scheduled` | every operation re-run against the real upstreams on a schedule | [`.github/workflows/connectors-live.yml`](../../../.github/workflows/connectors-live.yml) (cron `17 4 3 * *`): uploads its report, commits nothing | defined; no scheduled run is recorded in the repository |

Not covered by any level here: the edge gateway's own checks (`studio/edge/src/sources.js`: origins, templates, hosts, redirects, sizes, limits). They are unit-tested against a small synthetic registry (`studio/edge/test/sources.test.js`), and `studio/e2e/browser-access.spec.mjs` sends one operation (`connector.mygene.gene`) through them with a mocked upstream when Pyodide's CDN is reachable; no record of that run is committed. The post-deploy check (`studio/edge/scripts/check.mjs --require-sources`) reads the deployed gateway's health counts and calls no operation.
